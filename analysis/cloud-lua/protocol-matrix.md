# Cloud Protocol Compatibility Matrix

The production `cloud.lua` payload remains opaque. Each operation below is derived from the designated committed historical plaintext client; local backend tests only establish server compatibility and do not upgrade production x86LUA evidence.

| Operation | Method/path | Legacy request | Production static evidence | Backend behavior | Compatibility result | Evidence level |
| --- | --- | --- | --- | --- | --- | --- |
| heartbeat | `POST /heartBeat` | JSON body with `status` and `deviceToken`; no `assignmentId` or `clientVersion` | Unresolved: the endpoint and field tokens are absent from printable production strings | MockMvc binds omitted metadata as `null`; service tests accept the legacy heartbeat and retain halt handling | Compatible with the historical minimal body | Historical reference |
| get task | `GET /getTask` | Query parameter `deviceToken` | Unresolved: the endpoint and field tokens are absent from printable production strings | The request signature remains `deviceToken` only; the service blocks a device awaiting halt acknowledgement before assignment | Request shape remains compatible; production response handling is unresolved | Historical reference |
| add log | `POST /addLog` | Query `deviceToken` plus legacy JSON log fields; no independent `accountId` or `assignmentId` | Unresolved: the endpoint and field tokens are absent from printable production strings | MockMvc binds the legacy JSON and leaves new identity fields `null` | Compatible with the historical log payload | Historical reference |
| upload image | `POST /uploadImage` | JSON body with `base64Image` and `deviceToken`; not multipart | Unresolved: the endpoint and field tokens are absent from printable production strings | The existing JSON DTO endpoint is unchanged and no new required request field was introduced | Compatible by unchanged backend request contract; no focused upload runtime test | Historical reference |
| complete task | `POST /completeTask` | Empty body; query `deviceToken` and `imageUrl`; no `assignmentId` | Unresolved: the endpoint and field tokens are absent from printable production strings | MockMvc binds omitted `assignmentId` as `null`; service closes the current device assignment for the legacy request | Compatible with legacy completion | Historical reference |
| fail task | `POST /failTask` | Empty body; query `deviceToken`, `imageUrl`, and failure field `type`; no `assignmentId` | Unresolved: the endpoint and field tokens are absent from printable production strings | MockMvc binds omitted `assignmentId` as `null`; service accepts the current device assignment while rejecting explicit mismatches | Compatible with legacy failure reporting | Historical reference |
| sanity report | `POST /sanReport` | Empty body; query `san`, `maxSan`, and `deviceToken`; no `assignmentId` | Unresolved: the endpoint and field tokens are absent from printable production strings | MockMvc accepts the legacy query and updates the account from the current device assignment | Compatible with the historical sanity report | Historical reference |
| halt complete | `POST /haltComplete` | JSON body with `status` and `deviceToken`; no assignment metadata | Unresolved: the endpoint and field tokens are absent from printable production strings | The shared heartbeat DTO accepts missing metadata; service acknowledgement is idempotent and clears all duplicate halt entries under the halt-list lock | Compatible with legacy halt acknowledgement | Historical reference |
